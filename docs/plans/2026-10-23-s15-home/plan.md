# S15 — Главная: план

Контракт — [specification.md](specification.md) (R1–R11, примеры A1–A19). Он главнее этого плана.
Ветка `flow/s15-home`, checkout `/Users/underlow/Projects/PlezyTV`.

## 1. Результат

На TV раздел «Главная» оболочки `TvSectionShell` показывает свой `TvHomeScreen` вместо `DiscoverScreen`:
hero по фокусу, ряд «Продолжить просмотр», видео-хабы, карточка «Все», скелетон, экран ошибки, пустая
главная, действия OK / Play/Pause / меню. Данные — только `DiscoverProvider` без изменений.

## 2. Подход и общие договорённости

- Новый код — `lib/plezytv/tv_ui/home/` (экран, модель, адаптер воспроизведения) и
  `lib/plezytv/tv_ui/components/` (переиспользуемые визуальные компоненты). Тесты —
  `test/plezytv/tv_ui/`.
- Апстрим не правится, кроме одной строки в fork-файле `lib/plezytv/tv_ui/shell/tv_section_shell.dart`
  (выбор `TvHomeScreen` для `NavigationTabId.discover`). `DiscoverScreen`, `DiscoverProvider`,
  `tv_browse_rail.dart`, `media_detail_screen.dart` и прочие большие файлы не меняются.
- Компоненты S6 (`TvEpisode`, `TvPoster`, `TvHorizontalRow`, `tv_skeletons.dart`, `TvRatings`,
  `TvButton`, `TvFocusable`, `TvTintedBackground`) используются; расширяются только при нехватке и без
  изменения поведения существующих вызовов (их тесты должны проходить).
- Тексты — в `TvStrings` (как принято в fork-слое).
- Размеры и цвета — из `tv_tokens.dart` / `docs/design/tokens.json`, раскладка — `design-system.md`
  §5 и `screens.md` §1, §7, PNG `01-home-*`, `07-state-loading-home.png`, `09-state-error-server.png`.
- Проверки разработчика: `dart format` изменённых файлов, `flutter analyze`, тесты своих файлов и
  `test/plezytv/`. Полный `scripts/run_tests.sh` — в задаче T5.

## 3. Задачи

### T1 — Hero и карточка «Все»
Результат: в `components/` визуальные `TvHero` и карточка «Все» с тестами.
- `TvHero` получает `MediaItem?` и режим (обычный 600 / сжатый 420) и рисует по R1: логотип
  (`clearLogoPath`, не больше 560×200, в сжатом меньше) или название; метаданные (эпизод —
  `TvStrings.episode`, длительность, `TvStrings.left`); `TvRatings`; описание 3 строки (2 в сжатом).
  Не фокусируется, кнопок нет. Смена высоты анимируется, кроме `DevicePerformance.isReduced`.
  Скелетон hero (лого, строки метаданных и описания, `bg.skeleton`/`bg.skeletonLine`) — тут же или в
  `tv_skeletons.dart`.
- Карточка «Все»: фокусируемая карточка размера ряда (широкая или постер) с подписью, `onSelect`.
- Без знания о провайдере и навигации.
Проверки (widget-тесты): эпизод даёт `S{n} E{m} · title`, длительность и «… left»; без логотипа —
название; сжатый режим — 2 строки описания; reduced — без анимации высоты; hero не получает фокус.
Ловят: неверные метаданные эпизода, фокусируемый hero, анимацию на слабом устройстве.
Зависимости: нет.

### T2 — Адаптер воспроизведения для Play/Pause
Результат: функция/класс в `home/`, которая по `MediaItem` выполняет R5 для Play/Pause.
- Фильм, эпизод — `navigateToVideoPlayer` с продолжением с места остановки, как это делает Plezy для
  «Продолжить».
- Сериал — on-deck эпизод сериала с его сервера через `MediaServerClient.fetchItemWithOnDeck`
  (тот же источник, что у карточки сериала Plezy, `media_detail_screen.dart` ~849; не по превью `onDeck`
  провайдера, которое ограничено 20), иначе первый эпизод (примитивы `episode_collection.dart`:
  `defaultPlaybackSeason`, `fetchFirstEpisodeForSeason` и т. п.); сезон — первый эпизод сезона.
  Клиент выбирается по серверу элемента.
- Коллекция, нет эпизодов, ошибка получения — открыть карточку элемента (`navigateToMediaItem` без
  `playDirectly`).
- Не копировать код `media_detail_screen.dart`; зависимость от сети/клиента — через существующие API,
  чтобы адаптер тестировался с подменами.
Проверки (unit/widget с фейками): A15, A15b, A15c; настройки «карточка» не мешают Play/Pause; сериал,
чей on-deck эпизод не входит в превью провайдера, запускает этот эпизод, а не первый; одинаковый id
сериала на двух серверах — запрос идёт к серверу элемента.
Ловят: открытие карточки вместо воспроизведения, «следующая серия» для сезона, падение на пустом сериале.
Зависимости: нет.

### T3 — Модель экрана из провайдера
Результат: чистая модель в `home/` — из состояния `DiscoverProvider` список рядов и состояние экрана.
- Ряды: «Продолжить просмотр» (если `onDeck` не пуст) с флагом «есть ещё» = `hasMoreContinueWatching`;
  хабы в порядке провайдера без хабов `isContinueWatchingHub`; элементы только видов movie, show, season,
  episode, collection (R3); хаб без таких элементов скрыт; флаг «есть ещё» = `hub.more`; счётчик —
  `hub.size`, если фильтр ничего не убрал, иначе нет.
- Состояние частей: onDeck loading / ready; хабы loading / ready; экран: loading (ничего нет и что-то
  грузится), error (`errorMessage` и данных нет), empty (загружено, рядов нет), content.
- Идентичность элемента — с учётом сервера (один id на двух серверах — разные элементы), для
  восстановления фокуса.
- Ряды пересчитываются только при смене списков провайдера (идентичность списков, как в
  `DiscoverScreen`), а состояние экрана и частей вычисляется из текущих полей провайдера при каждом
  изменении (`isLoading`, `areHubsLoading`, `errorMessage`, `isLoadInFlight` меняются без замены списков,
  `discover_provider.dart` ~417, ~544).
Проверки (unit): A7, A9, A9b, A10, A10b, A11; loading → error → повтор → loading при тех же экземплярах
списков даёт правильное состояние на каждом шаге; дубль хаба «Продолжить» скрыт; хаб с альбомами и
`more=true` скрыт; счётчик отфильтрованного хаба отсутствует.
Ловят: показ музыки, дубль ряда, путаницу error/empty, слияние элементов разных серверов.
Зависимости: нет.

### T4 — Экран `TvHomeScreen` и встраивание в оболочку
Результат: экран в `home/`, подключённый в `tv_section_shell.dart` вместо `DiscoverScreen`.
- Раскладка: hero (T1) сверху, ряды (T3) через `TvHorizontalRow` с `TvEpisode`/`TvPoster`, в конце
  ряда с «есть ещё» — карточка «Все» (T1); фон `TvTintedBackground` по элементу в фокусе с задержкой
  300 мс (R1); текст hero меняется сразу; смена hero не перестраивает ряды (R10).
- Навигация R4: старт на первой карточке; ↑/↓ между рядами с памятью позиции, иначе первая видимая;
  ↑ из первого ряда — ничего; ← из первой колонки — в меню оболочки (как сейчас делает S12 для
  контента); hero 420 ниже второго ряда, ряд под hero; «Назад» — к началу ряда, затем оболочке.
- Состояния R6–R8: скелетон hero + два ряда, если данных нет дольше 300 мс; ряд хабов скелетоном,
  пока хабы грузятся; экран ошибки (макет 09: текст, «Повторить» в фокусе, во время повтора неактивна
  с `TvStrings.connecting`); пустая главная «Здесь пока пусто» + «Обновить». Повтор/обновление —
  `refreshNow()`/`load()`, неактивно при `isLoadInFlight`.
- Владение фокусом R6: автоматический уход в меню при загрузке и фокус кнопки повтора/обновления
  отдают фокус первой карточке при приходе данных, только если главная — текущий раздел, поверх нет
  маршрута и пользователь сам не уходил.
- R9: реализует `Refreshable`, `ManualRefreshable`, `FullRefreshable` (`primeRefresh`, `fullRefresh`),
  `TabVisibilityAware`, `FocusableTab` с теми же вызовами провайдера, что `DiscoverScreen`
  (`discover_screen.dart` ~556–660), без лишнего полного прохода на холодном старте; возврат на экран
  сохраняет фокус и прокрутку; исчезнувший элемент — сосед в ряду, иначе первая карточка.
- Расширение `TvHorizontalRow` (обратно совместимое; существующие вызовы и `tv_horizontal_row_test.dart`
  не меняют поведения): сейчас ← на первой карточке поглощается (~118–130), память позиции — по индексу
  (~189), после удаления только clamp (~57–62). Нужно: ← на первой карточке не поглощается (уходит
  наружу, оболочка открывает меню); метод «к началу ряда» для «Назад» (с отчётом, был ли уже в начале);
  память и восстановление позиции по ключу элемента, а не индексу — при удалении или перестановке фокус
  остаётся на том же элементе, иначе на соседе; уведомление о карточке в фокусе для hero.
- Действия на карточках в этой задаче — только OK через `navigateToMediaItem` с тем же
  `playDirectly`, что передаёт `tv_browse_rail.dart` для рядов «Продолжить» (R5), и «Все» — тот же
  `HubDetailScreen`, что открывает `tv_browse_rail.dart` (~1180–1200; для «Продолжить» — с
  `DiscoverProvider.loadAllContinueWatching` и теми же флагами). Play/Pause и меню — T5.
- Без TV / TV-интерфейс выключен — ничего не меняется (R11).
Проверки (widget-тесты с фейковым провайдером, по образцу `tv_section_shell_test.dart`): A1–A4, A8,
A9b, A10, A10b, A10c (через оболочку), A10d, A11, A12, A16 (открытие «Все»), A17, A18, A19; оболочка
вызывает `primeRefresh`/`refresh`/`onTabShown` у нового экрана; существующие тесты оболочки проходят.
Фокус R6 отдельно: пользователь сам ушёл в меню во время загрузки — данные пришли, фокус в меню; поверх
открыт маршрут — данные пришли, фокус не уходит; повтор/обновление снова дали ошибку или пусто — фокус
на кнопке. Ряд: ← с первой карточки → меню; «Назад» из прокрученного ряда → начало, второй — оболочке;
удаление/перестановка элемента в фокусе. R10: в ряду строится не больше видимых карточек плюс запас
(счётчик построений); перемещение фокуса меняет hero, не перестраивая ряды (счётчик построений рядов);
картинки карточек запрашиваются через существующий загрузчик с размером карточки (тест или проверка
кода с указанием места).
Ловят: кражу фокуса из меню, потерю позиции ряда, скелетон-мигание, неверную ветку error/empty,
пропущенные хуки оболочки.
Зависимости: T1, T3.
