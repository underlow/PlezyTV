# S4 — Настройки: экспорт и импорт на TV и через adb

Проект: `docs/projects/plezy-tv/project.md`, этап S4. Запрос этапа: «Экспорт и импорт настроек на телеке и командами
adb без пульта, чтобы раскатывать одни настройки на три телека; без утечки токенов. Встроить в снимки скилла `tv`.
После S1, от экранов не зависит.»

## 1. Цель и объём

В Plezy уже есть экспорт и импорт настроек (`lib/services/settings_export_service.dart`): закрытый список переносимых
настроек без учётных данных, настройки библиотек перепривязываются к пользователю. На TV раздел скрыт
(`settings_screen.dart`, `_buildBackupSection` только не на TV), экспорт пишет во внутреннюю папку приложения, импорт
требует окна выбора файла, которого на Android TV нет; через adb ничего нет. Этап открывает этот механизм на TV и
через adb и подключает его к скиллу `tv`.

Не входит: перенос по сети или облако, история поиска, учётные данные и адреса серверов, изменения на телефоне и
десктопе, свой механизм вместо механизма Plezy.

## 2. Требования

- **R1. Состав.** В файле — то же, что экспортирует Plezy (её список переносимых настроек; настройки библиотек
  привязываются к вошедшему пользователю на целевом устройстве), плюс настройки PlezyTV («Показывать загрузки»,
  раскладка клавиатуры поиска). Токенов, адресов серверов, истории поиска, путей на устройстве нет. Формат как у Plezy:
  файл Plezy с телефона импортируется в PlezyTV; ключи PlezyTV, неизвестные Plezy, пропускаются.
- **R2. Одно место.** Один файл `plezytv-settings.json` в папке приложения; экспорт (с TV и по ссылке) перезаписывает
  его, импорт читает его. По adb файл доступен через провайдер приложения
  `content://com.underlow.plezytv.settings/settings.json` без root и debug-сборки:
  `adb shell content read --uri … > файл` скачивает текущий файл, `adb shell 'content write --uri …' < файл` кладёт
  новый. Провайдер обслуживает только adb (shell) и root; другим приложениям — отказ.
- **R3. На TV.** В настройках TV раздел «Резервная копия» с «Экспорт» и «Импорт». Экспорт сообщает путь к файлу.
  Импорт спрашивает подтверждение (как в Plezy) и читает файл из R2. Понятные ошибки: файла нет, файл повреждён,
  никто не вошёл; при ошибке настройки не меняются.
- **R4. Через adb.** Ссылки `plezytv://settings/export` и `plezytv://settings/import`. Импорт по ссылке — без
  подтверждения. Ссылка ждёт выбора профиля, как ссылки экранов S5. Результат (успех с числом ключей или причина
  ошибки) — в лог с тегом `PlezyTV`; на экране — короткое уведомление. Порядок по adb: экспорт — ссылка, затем
  `content read`; импорт — `content write`, затем ссылка.
- **R5. Применение.** Импортированные настройки действуют сразу, как после импорта в Plezy, без перезапуска.
- **R6. Скилл `tv`** (репозиторий `~/Projects/things`, `.claude/skills/tv`, отдельный коммит там). Снимок запускает
  экспорт и скачивает `plezytv-settings.json` в папку снимка через `content read`; файл без токенов и идёт в git.
  Отдельная команда раскатывает файл на указанный телек (`content write` + ссылка импорта; на Android 9 без
  `content write` — `adb push` в папку приложения, не проверено); это запись на устройство — по правилам скилла
  только после явного «да».
- **R7. Остальное как было.** Экспорт и импорт на телефоне и десктопе не меняются. Ссылки `plezytv://screen/...`,
  `play`, `live` не меняются.

Проверено на приёмке 2026-10-26: на Xiaomi (Android 11) adb не может читать и писать
`/sdcard/Android/data/com.underlow.plezytv/files/` (`Permission denied`: каталог `u0_a… ext_data_rw`, у shell нет
этой группы), поэтому канал adb — провайдер. `content read`/`content write` на Xiaomi есть. Не проверено: Android 9
(Mi Box 4) — есть ли там `content write` и доступ к `Android/data`.

## 3. Примеры приёмки

| ID | R | Состояние | Действие | Ожидаемо |
|---|---|---|---|---|
| A1 | R1, R2, R4 | PlezyTV на TV, профиль выбран | adb: ссылка экспорта, затем `content read` | Файл есть, в нём настройки и ключи PlezyTV, нет токенов и адресов серверов |
| A2 | R2, R4, R5 | TV, профиль выбран | adb: `content write` изменённого файла, ссылка импорта | Настройки применились без перезапуска, в логе `PlezyTV` успех |
| A3 | R3 | TV, пульт | Настройки → Резервная копия → Экспорт | Сообщение с путём к файлу |
| A4 | R3 | TV, пульт | Импорт → подтвердить; отдельно — без файла и с повреждённым файлом | Применилось; иначе понятная ошибка, настройки не изменились |
| A5 | R4 | Приложение на выборе профиля | adb: ссылка импорта, затем выбрать профиль | Импорт выполняется после выбора |
| A6 | R1 | Файл экспорта Plezy с телефона | Положить в R2, импортировать на TV | Импортируется |
| A7 | R6 | Скилл `tv`, два телека | Снимок первого; раскатка на второй с подтверждением | Файл в папке снимка; настройки на втором применились |
| A8 | R2 | Другое приложение на TV | `content read`/`write` провайдера не от shell/root | Отказ; проверяется тестом |

## 4. Подтверждение

Подтверждено пользователем 2026-10-26 (включая импорт через adb без подтверждения на экране). Решения пользователя:
канал — файл в известном месте + кнопки на TV + ссылки adb; состав — Plezy + настройки PlezyTV; доработка скилла
`tv` — в этом этапе. Профиль flow — small; разработку и исправления делает Codex. Пересмотр 2026-10-26 после приёмки на Xiaomi: канал
adb — провайдер `content read`/`content write` вместо прямого пути (R2, R4, R6, A1, A2, A8), подтверждён
пользователем.
