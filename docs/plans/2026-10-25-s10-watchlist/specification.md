# S10 — Watchlist: спецификация

Проект: [docs/projects/plezy-tv/project.md](../../projects/plezy-tv/project.md), этап S10.

## 1. Цель и рамки

Исходный запрос (этап S10): «Watchlist отдельным пунктом меню, с сортировкой и фильтром; „смотреть“, если есть на
сервере. После S3. Не проверено: есть ли в Plezy функционал „есть на сервере“ (плашка на `06-watchlist.png`) —
проверить в этапе. Макет — `docs/design/screens.md` и PNG; приёмка по скриншоту.»

Макеты: `docs/design/screens/06-watchlist.png`, `08-state-empty-watchlist.png`, `01-home-sidebar-expanded.png`
(место пункта меню), `docs/design/screens.md` §6–7.

Проверенная предпосылка (код Plezy в этом checkout): watchlist в Plezy есть — источники каталога
(`CatalogSource`, `supportsWatchlist`: Plex Discover, Trakt, Simkl, MAL, AniList, MDBList) отдают его через
`fetchRow(CatalogRowId.watchlist)` и умеют добавлять и удалять; Plezy показывает его в Explore для одного
выбранного источника, без сортировки и фильтров. Готового признака «есть на сервере» у элементов списка нет:
Plezy ищет копии на серверах по одному элементу (`CatalogLibraryMatcher.match`) только при открытии карточки
каталога. Проверка элемента — до 5 запросов на сервер (поиск по guid и по каждому из до 4 вариантов названия).
Матчер держит до конца сессии только находку, на которую ответили все ожидаемые серверы; «не найдено» и неполные
ответы (сервер не ответил, офлайн, не опрошен) истекают через 10 минут; смена набора серверов сбрасывает кэш.

Цель: отдельный TV-раздел «Список» с сортировкой, фильтрами, плашками «На сервере» и своей TV-карточкой для
элементов, которых на сервере нет.

Входит: пункт меню в оболочке S12, экран списка, переключатель источника, фоновая проверка наличия на сервере,
своя карточка каталога для входа из «Списка».

Не входит: Explore и карточка каталога Plezy для других входов (не меняются); объединение списков разных
источников в одну сетку; Lists/Recommended из Plex; ускорение проверки пакетными guid-запросами; «В ролях» и
«Похожие» на карточке каталога.

## 2. Требования

### Меню и оболочка

- **R1 Пункт меню.** «Список» стоит сразу после пунктов библиотек, перед «Ещё», Live TV, Explore и остальными
  (`01-home-sidebar-expanded.png`). Виден, когда есть связь и подключён хотя бы один источник каталога с watchlist.
  Офлайн пункта нет. Если все такие источники отключились, пока открыт «Список», пункт исчезает и оболочка
  переходит на «Главную». После потери и восстановления связи открытый «Список» восстанавливается, как другие
  разделы S12. Переключение разделов с пульта-компаньона включает «Список» на его месте в меню.

### Загрузка и шапка

- **R2 Загрузка.** Загружается весь список текущего источника страницами, до 1000 элементов; сетка появляется,
  когда загружены все страницы (порядок, счётчик и фильтры считаются по полному списку). Если элементов больше,
  показываются первые 1000. Скелетон сетки по правилам `screens.md` §7: не показывается, если данные пришли за
  300 мс, без анимации блеска; шапка и вкладки рисуются сразу. Ошибка любой страницы при первой загрузке — экран
  ошибки с «Повторить» (в фокусе); повтор загружает список заново.
- **R3 Шапка.** Заголовок «Список»; справа кнопки источника (только когда подключено больше одного источника с
  watchlist), сортировки «{сортировка} · {count}» и «Фильтры» («Фильтры · {n}», если фильтры активны). Под шапкой
  вкладки «Все / Фильмы / Сериалы / Есть на сервере». `{count}` — число элементов на текущей вкладке с учётом
  фильтров. На пустом экране и экране ошибки (R13, R2) при нескольких источниках остаются заголовок и кнопка
  источника (сортировка, фильтры и вкладки скрыты); ↑ с кнопки действия ведёт на кнопку источника. При одном
  источнике эти экраны — как макет `08` без шапки.
- **R4 Источник.** Кнопка источника показывает его название; OK открывает правую панель со списком подключённых
  источников с watchlist. По умолчанию — Plex Discover, если подключён, иначе первый подключённый в порядке
  Plezy. Выбор запоминается между запусками отдельно для каждого профиля; если запомненный источник отключён,
  берётся источник по умолчанию. Если открытый источник отключается, пока открыт «Список», а другие остаются,
  загружается источник по умолчанию; запомненный выбор не меняется и снова действует, когда источник подключат.
  При смене загружается список нового источника, фокус на первой карточке,
  вкладка и сортировка сохраняются, фильтры жанра и года сбрасываются.

### Сортировка, фильтры, сетка

- **R5 Сортировка.** В правой панели, как в S16: по дате добавления (новые первыми; по умолчанию), по названию
  (А–Я), по году (новые первыми), по оценке (выше первыми). Если источник не даёт дату добавления, «по дате
  добавления» — порядок источника, приведённый к «новые первыми», если источник известен как отдающий старые
  первыми; иначе как отдаёт источник. Элементы без года или оценки идут в конце.
- **R6 Фильтры.** Жанры (несколько) и десятилетия (несколько), значения — из элементов загруженного списка. Если ни
  у одного элемента нет жанров, раздел жанров в панели не показывается; так же для десятилетий. Фильтры и вкладка
  действуют вместе. Сортировка, фильтры и вкладка запоминаются между запусками отдельно для профиля; фильтры — до
  смены источника (R4). Сохранённое значение фильтра, которого больше нет в списке, при загрузке отбрасывается.
- **R7 Сетка.** Как в S16: 6 колонок 228×342 с подписями, фокус и прокрутка как в библиотеке, без колонки букв.
  Подпись элемента — по правилам Plezy для элемента каталога. У найденного элемента в фокусе перед подписью
  добавляется «На сервере · » (R8).

### Наличие на сервере

- **R8 Проверка.** После загрузки элементы проверяются в фоне матчером Plezy: сначала видимые и ближайшие, затем
  остальные; одновременно идёт ограниченное число проверок, чтобы на сервер не уходило больше нескольких десятков
  одновременных запросов. Результат элемента — «найден» (есть хотя бы одна копия, даже если какой-то сервер не
  ответил), «не найден» (ответили все серверы, копий нет) или «не проверен» (копий нет, но какой-то сервер не
  ответил, офлайн или не был опрошен). У найденного — плашка «На сервере»; у остальных плашки нет, ошибка на экран
  не выводится.
  Повторная проверка (идёт к серверам, минуя кэш матчера для неполных ответов):
  - элемент, по которому ответили не все серверы («не проверен» или «найден» не на всех), проверяется снова, когда
    меняется набор серверов или сервер выходит на связь; найденные копии при этом сохраняются, новые добавляются;
  - «не найден» проверяется снова при открытии раздела, если результату больше 10 минут (как живёт отрицательный
    ответ матчера);
  - «найден» на всех серверах не перепроверяется до конца сессии.
  Повторное открытие раздела и карточки каталога пользуются уже полученными результатами.
- **R9 Вкладка «Есть на сервере».** Показывает уже найденные элементы в выбранной сортировке. Пока проверка идёт и
  ничего не найдено, вместо пустого текста — «Проверяем, что есть на сервере…». Новые найденные элементы
  добавляются без переноса фокуса: элемент в фокусе остаётся в фокусе и на экране. Если проверка закончена и
  ничего не найдено — пустой текст по R13.

### Действия

- **R10 OK по элементу.** Найденный с одной копией — открывает карточку S8 или S7 этой копии; с несколькими —
  меню выбора копии (библиотека, сервер, качество, как список копий у Plezy), затем её карточку. Ненайденный или не
  проверенный — сразу открывает карточку каталога (R11). При возврате фокус на том же элементе; если элемента в
  списке больше нет — на соседнем (следующем, иначе предыдущем), как в S16.
- **R11 Play/Pause.** На найденном элементе физическая Play/Pause делает то же, что на главной S15 для элемента
  сервера: фильм — запуск или продолжение; сериал — следующая серия к просмотру, а если её нет — открывается
  карточка сериала. При нескольких копиях — первая в порядке Plezy. На остальных элементах ничего не делает.
- **R12 Карточка каталога.** Своя TV-карточка, одна для фильмов и сериалов, раскладка — шапка S8: логотип или
  название; год · длительность или число сезонов · возраст; жанры; оценки каталога; описание 4 строки. Данные
  элемента дополняются подробностями источника. Кнопки:
  - «Открыть» — первая, место занято всегда. При открытии карточка проверяет наличие (с уже известным результатом
    сетки и по дополненным данным, как Plezy). Пока проверка идёт — индикатор, кнопка неактивна (на слабом железе —
    статичный значок вместо вращения). Найдено — кнопка активна: одна копия — S7/S8, несколько — меню выбора
    копии (R10). Не найдено — «Нет на сервере», неактивна. Не проверено — «Не удалось проверить», активна, OK
    повторяет проверку. Неактивную кнопку фокус пропускает;
  - «Убрать из списка» из списка текущего источника, работает сразу, не дожидаясь загрузки данных о составе
    списка; после удаления — «Вернуть в список». Ошибка — сообщение как в Plezy, кнопка возвращается в прежнее
    состояние;
  - «Трейлер», если он есть у элемента.

  При открытии фокус на первой активной кнопке; появление результата проверки кнопки не сдвигает и фокус не
  переносит.

### Изменения, пустые состояния, совместимость

- **R13 Изменения списка.** Элемент, убранный из списка текущего источника (в карточке каталога, на S7/S8 или в
  любом другом месте приложения), при возврате в «Список» в сетке отсутствует сразу, без ожидания сети;
  добавленный в другом месте — появляется после фонового обновления. Фоновое обновление не показывает скелетон, не
  меняет фокус и прокрутку (кроме R10 для исчезнувшего элемента в фокусе) и сохраняет результаты проверки
  наличия. Ошибка фонового обновления оставляет прежний список без сообщения. Загрузка данных о составе списка
  (без изменений) обновления не вызывает.
- **R14 Пусто.** Пустой список — экран как `08-state-empty-watchlist.png`: иконка, заголовок, пояснение, кнопка
  «Перейти к поиску» в фокусе, она открывает раздел «Поиск» (шапка при нескольких источниках — R3). Пустая вкладка
  или пустой результат фильтров — текст «{Фильмов/Сериалов/…} в списке нет» на месте сетки, фокус остаётся на
  вкладках.
- **R15 Сохраняем.** Мобильный интерфейс, Explore и карточка каталога Plezy не меняются. Правила
  `docs/plezytv/tv-ui.md`: код в fork-owned файлах, большие файлы апстрима не правим; правки апстрима — только если
  без них нельзя, минимальные.

## 3. Дизайн

- **Раздел оболочки.** Upstream-enum `NavigationTabId` не трогаем. `TvShellSection` получает свою идентичность
  раздела «Список». `TvSectionShell` сейчас целиком построен на вкладках (ключи, `IndexedStack` по индексу
  вкладки, доступность, шаги пульта, восстановление после офлайна, переход в корень при недоступности,
  `handleContentIntent`), поэтому все эти места учитывают новый раздел: экран монтируется лениво рядом с
  остальными, доступность — связь плюс непустой `CatalogSourcesProvider.watchlistCapableSources`, оболочка
  слушает провайдер источников и переводит на «Главную», когда раздел стал недоступен. `refreshAfterResume` и
  `fullReset` для «Списка» — фоновое обновление (R13) и полная перезагрузка соответственно.
- **Контроллер списка** (`lib/plezytv/tv_ui/watchlist/`). Владеет текущим источником, загруженным списком
  (`CatalogSource.fetchRow(CatalogRowId.watchlist)` постранично), сортировкой, фильтрами и вкладкой; живёт, пока
  смонтирован раздел. Отфильтрованный и отсортированный вид отдаётся сетке через `TvPagedSource` поверх списка в
  памяти и `TvPagedGrid` из S16. Сетку дополняем, не меняя поведения S16: сообщение о видимом диапазоне (для
  приоритета проверки), обработка Play/Pause и сохранение фокуса по ключу элемента — при вставке или удалении
  элементов перед фокусом индекс фокуса пересчитывается и прокрутка компенсируется, чтобы элемент в фокусе
  остался на месте (R9, R13). Подписывается на `watchlistChanges` текущего объекта источника и переподписывается, когда
  `CatalogSourcesProvider` заменяет объект или отключает источник. `watchlistChanges` срабатывает и на загрузку
  данных о составе, и дважды на изменение, поэтому контроллер сравнивает состав по `isOnWatchlist`: исчезнувшие
  элементы убирает сразу (R13), а при расхождении назначает одно фоновое перечитывание с задержкой. Данные о составе
  (`ensureWatchlistLoaded`) контроллер запрашивает при загрузке списка и повторяет при неудаче. Карточка каталога
  сообщает контроллеру о своём удалении и возврате напрямую, не дожидаясь этих данных.
- **Дата добавления у Plex.** Plezy запрашивает watchlist Plex без сортировки и не разбирает дату, а у
  `CatalogItem` нет сырого ответа, поэтому fork-owned код дату прочитать не может. Решение пользователя: минимальная
  правка `PlexCatalogSource._fromMetadata` (`lib/services/catalog/plex_catalog_source.dart`) — `addedAt` из
  `watchlistedAt` (epoch-секунды или ISO-строка). Если Plex поле не отдаёт, `addedAt` пуст и действует правило R5.
  Побочный эффект — карточка каталога Plezy показывает «Добавлено» и для Plex, как уже для Trakt/Simkl/MDBList.
  Порядок Plex по умолчанию не подтверждён и не разворачивается. Жанры Plex читаются из `Genre` (`includeMeta=1`);
  наличие поля в ответе watchlist, как и `watchlistedAt`, проверяется на TV.
- **Служба наличия.** Очередь поверх `CatalogLibraryMatcher.match` с ограниченной параллельностью и приоритетом
  видимого диапазона. Хранит результат по элементу (найден с копиями, не найден, не проверен — по
  `failed/cancelled/unqueriedServerIds` результата) и время результата; слушает `MultiServerProvider` для
  повторной проверки неполных результатов (R8). Матчер возвращает неполный ответ из кэша 10 минут, и выход
  сервера на связь кэш не сбрасывает (`expectedServerIds` уже включает недоступные серверы). Поэтому в
  `CatalogLibraryMatcher.match` (файл апстрима ~200 строк) добавляется минимальный необязательный параметр,
  который для неполной записи кэша заново опрашивает серверы с прежним слиянием ответов; без параметра поведение
  Plezy не меняется. Им пользуются повторная проверка и «Не удалось проверить». Уведомляет сетку и вкладку. Смена источника снимает из очереди
  непроверенные элементы старого; уже идущие запросы дожидаются завершения, их результат игнорируется. Живёт,
  пока смонтирован раздел, и отдаёт известный результат карточке каталога.
- **Карточка каталога.** Свой экран в `lib/plezytv/tv_ui/`, открывается только из «Списка» (хук в апстриме не
  нужен). Данные элемента дополняет `CatalogSource.fetchDetail`; наличие проверяет тот же матчер по исходной и
  дополненной форме элемента, объединяя копии, как карточка каталога Plezy; «Убрать / Вернуть» — через
  `mutateWatchlistMembership` для текущего источника с id элемента; «Открыть» — через
  `navigateToMediaItemDetails`, то есть через хук S7/S8; меню копий — по образцу списка копий Plezy; «Трейлер» —
  как в карточке каталога Plezy. Собирается из компонентов S6 и шапки S8. Play/Pause в сетке использует
  `TvHomePlayback` из S15.
- **Предпочтения** (источник, сортировка, фильтры, вкладка) хранятся на профиль, так же как предпочтения
  библиотеки в S16.

## 5. Согласование

Подтверждено пользователем 2026-10-25 (профиль medium, Codex не используется). Решения пользователя: фоновая
проверка всех элементов; своя TV-карточка каталога (шапка и кнопки, без «В ролях» и «Похожих»); фильтры — жанр и
год; переключатель источника в шапке вместо объединения списков; «Открыть» на карточке — с индикатором и
неактивная до результата. После независимой проверки: по умолчанию Plex; «Список» сразу после библиотек; при
неудачной проверке — «Не удалось проверить» с повтором, при нескольких копиях — меню выбора копии; на пустом
экране и экране ошибки при нескольких источниках остаётся шапка с кнопкой источника.

Делегировано на усмотрение flow: точная параллельность и порядок проверки, лимит страниц, подпись сериала и
тексты пустых вкладок по правилам Plezy, форма индикатора в рамках компонентов S6, поведение «Трейлер» по
Plezy, способ получения даты добавления Plex.
После реализации T2 (2026-10-25) пользователь выбрал разбор `watchlistedAt` правкой `plex_catalog_source.dart` (§3).
