## 1. Подход

- T1 — модель: вид ряда (постеры / музыка) в `TvHomeModelBuilder`, отбор элементов по виду, «Продолжить» и поиск S11 —
  только постеры.
- T2 — компоненты: музыкальная карточка (квадрат / круг для исполнителя) с подписями, квадратная «Все», строка hero
  для музыки.
- T3 — интеграция на главной: ряды по виду, выбор карточки, Play/Pause при музыкальной сессии, документация.

T1 и T2 независимы; T3 зависит от обоих.

## 2. Общие контракты

**C1. Вид ряда (T1 → T3).** `TvHomeRow` получает публичный признак вида: постеры (как сейчас) или музыка. Правило
отбора хаба (R1): «видео-набор» — как нынешний `_videoItems` (movie, show, season, episode, collection);
«музыка» — artist, album, track. Вид хаба — вид первого элемента, входящего в один из наборов; в ряд попадают
только элементы этого вида в исходном порядке; хаб без таких элементов пропускается. Счётчик — как сейчас
(`hub.size`, только если ничего не отброшено). Ряд «Продолжить просмотр» — только видео-набор, как сейчас.
`itemKey`, кэширование по identity и состояния (`loading`/`error`/`empty`/retry) не меняются; музыкальный ряд
считается рядом хаба для состояния `content`.

**C2. Музыкальная карточка (T2 → T3).** Публичный виджет в `tv_cards.dart` с тем же набором параметров, что у
`TvPoster` (item, client, focusNode, autofocus, onSelect, onLongPress, onFocusChange, externalFocus — по нужде
T3). Размер 216×216 дизайна (`TvTokens.size.poster.w`; отдельный токен — на усмотрение разработчика, без изменения
`docs/design/tokens.json`). Под обложкой — те же отступ (20) и две строки, что у постера, поэтому высота ряда =
216 + 20 + body + caption. Исполнитель: круглая обложка, рамка фокуса круглая (`radius` как у
`TvPersonCard`), вторая строка пустая. Альбом / трек: квадрат с `radius.card`. Подписи R2 строго по геттерам
`MediaItem`: альбом — `albumArtistTitle`; трек — `trackArtistTitle` · `albumTitle`; пустые части пропускаются без
«·».
Увеличение в фокусе — `cardScale` от нижнего края. Нет бейджей (включая ✓), прогресса и «N не просмотрено» (R3).
Картинка — `thumbPath ?? parentThumbPath` (у трека `parentThumbPath` — обложка альбома), иначе заглушка
`surface.level2`. Фон главной (`TvTintedBackground`) не меняется: у трека без своей `thumbPath` окраски нет —
принято (у треков Plex обычно своя обложка). `TvAllCard` получает квадратный вариант того же размера; его
текущие вызовы не меняются.

**C3. Hero (T2).** `TvHero` для artist/album/track строит строку метаданных R6 (альбом: `albumArtistTitle` · `year`
· `genres`; трек: `trackArtistTitle` · `albumTitle` · длительность; исполнитель: `genres`), без возрастного рейтинга и без `TvRatings`;
пустые части пропускаются. Для видео поведение без изменений.

**C4. Play/Pause при музыке (T3).** `tvHomeCardKeys` получает новый параметр — признак музыкальной сессии
(например `bool Function() musicActive`); вызывающие передают
`() => context.read<MusicPlaybackService?>()?.currentTrack != null` (nullable-чтение обязательно: в тестах TV UI
сервиса нет, `read<MusicPlaybackService>()` бросит `ProviderNotFoundException`). Все три места вызова:
`TvHomeHubCard` (`tv_home_card.dart:70`) и `_cardKeys` поиска (`tv_search_screen.dart:873`, используется в
`:928` и `:971`). При активной сессии play/toggle → `ignored` и `activate` не вызывается. Глобальный обработчик
музыки Plezy (`HardwareKeyboard`) Flutter вызывает раньше дерева фокуса независимо от ответа карточки — `ignored`
лишь убирает второе действие; не менять на `handled` в расчёте «перехватить» клавишу, это ничего не даёт.
«Припаркованная» после запуска сессия обработчика не имеет — Play/Pause тогда ничего не делает, это принятое
ограничение (spec R4, A22). Без сессии — как сейчас. «Меню» не меняется.

## 5. Итог (2026-10-26)

Готово: на TV-главной S15 показываются музыкальные хабы — ряды исполнителей, альбомов и треков квадратными карточками
216×216 (исполнитель — круглая, с круглой рамкой), подписи по полям Plezy, без статуса просмотра; квадратная «Все»;
hero со строкой для музыки без оценок; OK / Play / «Меню» — действия Plezy. Пока у Plezy есть текущий трек,
Play/Pause на карточках главной и поиска не запускает карточку (кнопкой управляет музыка). «Продолжить просмотр» и
пустой экран поиска S11 — только видео. Коммиты: T1 `1854446c6`, T2 `7b0603a15`, T3 `e0d6389e2`, исправления тестов
по ревью `6ac4daf3e`. Апстрим не правился.

Проверки: полный прогон `scripts/run_tests.sh` после T3 — 9028 passed / 7 skipped / 0 failed (отчёт разработчика);
после исправлений тестов `test/plezytv/tv_ui/` — 811 passed (перезапущено координатором); `flutter analyze` по
изменённым файлам без замечаний. Независимые ревью всего изменения (Opus, поведение и качество тестов): по поведению
находок нет; по тестам — 4 мелких, исправлены (`6ac4daf3e`), одна снята проверкой; повторное ревью исправления не
проводилось — координатор проверил дифф и перезапустил тесты.

Принятые ограничения: после запуска с восстановленной («припаркованной») музыкой Play/Pause на карточках ничего не
делает, пока музыку не запустят (R4, A22); у трека без своей обложки фон не окрашивается. Не проверено: вид на TV
(приёмка по скриншоту против спецификации), Play/Pause на реальном пульте при играющей музыке (A15), Jellyfin вживую.

Вне объёма, для проекта: плейлисты на главной не делались — клиент Plex Plezy отбрасывает их до главной, нужен свой
запрос и своё открытие плейлиста; фото и клипы пользователю не нужны.
